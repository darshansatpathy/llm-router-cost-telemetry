# Replay through the gateway

Generated by `llmrouter replay`: the 2,000 held-out RouteLLM prompts, plus 500 of them asked again later, sent one task each through the real gateway (router, Redis 8 cache, cascade, task accounting), with each backend replaying the answer that model actually gave. A task whose small-model answer the judge scored below 4 is retried on the large tier and charged for both calls.

Router threshold 0.878; semantic cache threshold 0.995.

| Policy | Tasks | Right first time | Wrong answers if nothing caught them | Retries | Small / large calls | Cache hits | Cost per completed task | vs always large |
|---|---|---|---|---|---|---|---|---|
| always large | 2,500 | 100.0% | 0.0% | 0 | 0 / 2,500 | 0 | $0.00829 | +0.0% |
| always small | 2,500 | 86.0% | 14.0% | 349 | 2,500 / 391 | 0 | $0.00146 | -82.4% |
| router | 2,500 | 96.6% | 3.4% | 86 | 1,397 / 1,217 | 0 | $0.00371 | -55.2% |
| router + cache | 2,500 | 96.6% | 3.4% | 86 | 1,122 / 1,002 | 487 | $0.00308 | -62.8% |

How to read this. The retries assume a perfect oracle: the agent knows exactly which answers were bad and asks again only for those. With that oracle, always using the small model is cheapest, because the large model costs about 20 to 50 times more per token. Production has no oracle: an undetected weak answer goes to the user. That is the column that matters: always-small leaves 14.0% of answers wrong, the router 3.4%, at -55% cost against always-large. The exact cache then answers repeated questions for nothing.

Routing adds one MiniLM embedding per request (the prompt truncated to 256 tokens): a median of 41 ms per request in the router run of this replay on a shared two-core machine, and several hundred milliseconds while other jobs held both cores. Give the gateway its own cores, or run the embedder on a GPU.
